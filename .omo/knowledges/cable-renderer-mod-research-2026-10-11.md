# Cable renderer inspiration from existing mods (2026-10-11)

Scope: source inspection only; no Minecraft runtime validation or new rendered candidates in this research pass. Preserve the finalized Federation cable shell. Source snapshots were fetched from public GitHub API/raw endpoints.

## Sources and verified mechanisms

- [Draconic-Inc/Draconic-Evolution / CrystalFXBeam.java](https://github.com/Draconic-Inc/Draconic-Evolution/blob/6251e32bc93eb4bfcd910236ec1eaa6546516229/src/main/java/com/brandon3055/draconicevolution/client/render/effect/CrystalFXBeam.java): Four axial crossed quads; moving longitudinal UV; full-bright vertices; SRC_ALPHA/ONE additive blending; depth writes disabled; optional camera-facing endpoint sprites. Beam scale follows powerLevel, exponentially approaching fxState.
- [Draconic-Inc/Draconic-Evolution / reactor_beam.fsh](https://github.com/Draconic-Inc/Draconic-Evolution/blob/6251e32bc93eb4bfcd910236ec1eaa6546516229/src/main/resources/assets/draconicevolution/shaders/core/reactor_beam.fsh): Separate reactor effect: seven noise octaves, Time/Power/Fade/Startup/Type uniforms. ReactorBeamFX uses triangle strips around the axis. Do not confuse this shader with the simpler crystal beam implementation.
- [Direwolf20-MC/LaserIO / RenderUtils.java](https://github.com/Direwolf20-MC/LaserIO/blob/4d278a6351a434d343fbf70d942baeeaf2607536/src/main/java/com/direwolf20/laserio/client/renderer/RenderUtils.java): View-oriented beam quad from a cross product with the player eye direction; full-bright and scrolling V. Device/card beams have separate beam/core passes, while node connections use CONNECTING_LASER. MyRenderType uses standard translucent blending, not additive, even for a field named LASER_MAIN_ADDITIVE (marked unused).
- [GaLicn/ME-Beam-Former / BeamRenderHelper.java](https://github.com/GaLicn/ME-Beam-Former/blob/71c1a53ae1d0e19115b3d2f6ac75b43edcbb2ed8/src/main/java/com/mebeamformer/client/render/BeamRenderHelper.java): GaLicn standalone ME Beam Former, master snapshot (uses 1.20-style APIs): vanilla beacon texture and beaconBeam render type; two square-prism shells with outer scale 1.18/alpha .22, core scale .62/alpha .90, white mix .16; full brightness and UV scrolling. Not NAE2 legacy implementation.
- [AE2-Lightning-Tech-Reborn/AE2-Lightning-Tech-Reborn / RailgunBeamRenderClient.java](https://github.com/AE2-Lightning-Tech-Reborn/AE2-Lightning-Tech-Reborn/blob/2d8369e1e8b952300ec7ee73837e75cb61c7fc8d/src/main/java/com/moakiee/ae2lt/client/railgun/RailgunBeamRenderClient.java): Reborn continuation, explicitly not proof of original deleted upstream version: 12 longitudinal segments, three square-prism layers with different/opposed rotation rates; moving sine-wave vertex alpha; endpoint flash; periodically spawned arcs. Uses additive blending with depth testing retained.
- [AE2-Lightning-Tech-Reborn/AE2-Lightning-Tech-Reborn / RailgunArcRenderer.java](https://github.com/AE2-Lightning-Tech-Reborn/AE2-Lightning-Tech-Reborn/blob/2d8369e1e8b952300ec7ee73837e75cb61c7fc8d/src/main/java/com/moakiee/ae2lt/client/railgun/RailgunArcRenderer.java): Random offset polyline with endpoint attenuation 4*t*(1-t); three camera-facing layers; sqrt lifetime alpha decay; additive blending, depth test on, depth writes off, parallel-view fallback. Inspected code decrements remaining in render callback, so do not copy its lifetime scheme: prefer tick/time-based lifetimes.
- [AE2-Lightning-Tech-Reborn/AE2-Lightning-Tech-Reborn / OverloadedCableRenderHelper.java](https://github.com/AE2-Lightning-Tech-Reborn/AE2-Lightning-Tech-Reborn/blob/2d8369e1e8b952300ec7ee73837e75cb61c7fc8d/src/main/java/com/moakiee/ae2lt/client/render/OverloadedCableRenderHelper.java): The overloaded cable helper builds static BakedQuads via CubeBuilder; railgun plasma effects are a different renderer, not evidence that its cables use plasma shaders.

Original ae2lt/AE2-Lightning-Tech API returned 404 during inspection. Checked gjmhmm8 and bfzds backups for discovery; the detailed railgun analysis above is pinned to Reborn commit 2d8369e1e8b952300ec7ee73837e75cb61c7fc8d.

## Design inference for Federation

- Prioritize a stable pale core, saturated low-opacity shoulder, restrained moving plasma detail and sparse short-lived arcs. The previous geometric studies need stronger emissive-layer separation, not simply more geometry.
- Keep all opaque shell occlusion. Full-bright/emission and additive blending are distinct from bloom; none makes opaque rails transparent. Blender emission strength alone does not reproduce Minecraft framebuffer blending.
- Next concepts: confined plasma stream; a thin luminous double helix; a stable core with sparse arc discharges; short photon-gate packets. These are proposals, not implemented results of this pass.
- World/path-distance phase is required across blocks and elbows; point-to-point beam code does not solve arbitrary cable junctions. Current Federation BEND/HUB phases are static.
- Use sparse, time-based effect events and distance-based detail levels. Keep an ordinary translucent fallback if experimenting with an additive pass; verify shell/glass ordering in Minecraft.
- Reuse principles through original code; do not import third-party art or source without checking their licenses.
