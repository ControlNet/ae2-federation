# Blender rendering feasibility (2026-10-11)

- Offline block/item rendering is feasible using the existing production assets and Blockbench projects. No Blender pipeline was implemented during this advisory review.
- Prefer current `common/src/main/resources/assets/ae2federation/` models/textures for release illustrations. `tools/blockbench/versions/v01..v07` are frozen historical designs, not an authoritative representation of the current cable.
- Current cable geometry is generated by `FederationCableBuilder` and connection-dependent face selection by `CableCoreFaces`; consult `federation-cable-ae2-dense-2026-10-09.md`. Importing the static cable JSON alone cannot reproduce its runtime appearance. Reconstruct a selected connection state and handle the flow renderer separately.
- Flat generated items and block-backed items need different import handling. Flat item textures can be presented as textured planes or explicitly extruded meshes.
- Proposed first proof: one current Router, one current cable connection state, and one Nexus Processor, checking UV orientation, nearest-neighbor texture sampling, transparency, and material/color differences against game screenshots.
- Blender supports glTF import: https://docs.blender.org/manual/en/5.1/addons/import_export/scene_gltf2.html . A Blockbench export or a dedicated asset converter still needs to be validated; native Minecraft JSON / bbmodel import is not assumed.
- Blender output is suitable for illustrations and animations. Runtime Minecraft models and materials still require the existing game asset/rendering pipeline; a Blender render is not evidence of in-game correctness.
