# Custom-policy comparison: 100 projects (2026-10-03)

## Purpose and fixed product direction

Investigate richer resource filters, AE2/network/resource conditions and usable authoring for future Federation
policies. The agreed baseline remains simplified STORAGE/CRAFTING disabled/enabled/re-export states, with crafting
depending on storage for the same pair/direction, and a shared ME power pool with on/off control. This survey does
not re-audit the current implementation or revive older filter fields as an already-approved baseline.

The user endorsed future storage filtering and condition inputs beyond redstone. They require connected-node
editing AND Python/Lua-like script editing, freely convertible while continuing to author in either representation,
with comprehensive completion and contextual preset/item icons. No language, runtime, dependency or implementation
architecture has been chosen. Product proposals are in [the policy idea](../../docs/ideas/custom-policies.md);
[earlier discussion and corrections](custom-policy-ideas-2026-10-02.md) preserve the history.

## Most useful findings

| Design question | Strong reference patterns | Federation implication, still a proposal |
|---|---|---|
| What does a resource filter select? | RS Relay, Mekanism, Pipez, Sophisticated Storage, ExtendedAE: explicit item/tag/mod/data matching | Describe matching scope and empty-filter behavior; avoid conflating a display search with enforced resource access |
| What does a quantity mean? | LaserIO, SFM, Modular Routers, AdvancedAE, Simple Storage Network: source retention, destination stock and transfer amounts | Keep source reserve, target stock, receiving ceiling, batch, rate and shared quota distinct |
| Which conditions are useful? | AE2 emitter, Advanced Peripherals ME API, XNet, IE Machine Interface, Integrated Dynamics/Tunnels | Label the observed network, resource view, units and available metrics; validate the selected AE2 API/version |
| How do conditions compose? | Integrated Dynamics/Crafting, SFM, PneumaticCraft, Create, In Control | Explore Boolean combinations, named conditions, group scope, state transitions and explicit precedence |
| Why did a rule not act? | Integrated Tunnels status, Project Red Fabrication compiler problems, Redstone Pen live variables, In Control statistics | Show observed values and the effective decision, and connect diagnostics to graph nodes and script locations |
| How do players enter resources? | FTB Filter System JEI dragging and match tests; AE2 ghost slots; ProbeJS item-literal completion | Combine actual resource picking, contextual completion and icons in the requested authoring experience |
| What does authority mean? | RS security cards, IC2 Classic slot rules, SecurityCraft ownership, FTB Teams | Distinguish resource visibility, operation permission and configuration authority; exact Federation extensions remain open |

The numbered entries below provide the primary links and version limits for each comparison. These proposals do
not approve reserve guarantees, quotas, operation-specific permissions, fallback precedence or every suggested
observable. A stock threshold alone cannot guarantee retained stock under concurrent extraction. A screen-only
filter does not enforce authorization. Team identity, network topology membership and access permission differ.

## Method and counting

The user explicitly requested approximately 100 mods for P2P and approximately 100 for policy, with overlap allowed.
Three parallel investigations and a parent review assembled 118 candidate projects and examined each through both
lenses. Each final catalog selects 100; **93 projects overlap, so the two catalogs cover 107 distinct projects**.
Their conclusions are different evaluations, not a reused claim that every wireless mod also implements policies.

Count separately published mod projects/modules, not blocks, Minecraft versions or loader ports. Thermal, RFTools,
Project Red and Integrated suites contain separately published modules but represent fewer design families than
their project count. Original/successor lineages and simple ports are consolidated where noted. Pipe and Pipez are
different authors/projects; the Cloud Storage entry is AlexModGuy's project. The CF and MR editions of one mod do
not create two entries. KilaGraph and KilaGraphDemo remain explicit user references outside the numbered sample;
they are not counted as popular technology mods to inflate it.

The sample is anchored in widely downloaded technology, storage, transport and automation mods, with clearly
identified scripting/protection tools and a few smaller specialist references. Download figures are approximate
lifetime platform counters observed on 2026-10-03 or returned in cached author-page results; CF = CurseForge,
MR = Modrinth. They establish scale, not unique players, active usage, a ranked top 100 or design quality. No
cross-platform totals are added. Smaller specialists are retained for distinctive relevant behavior, not described
as equally popular as AE2, Create or Mekanism. Applied Botanics is an AE2/Botania automation crossover.

Sources are author project descriptions, official manuals and author source repositories. The linked platform
page is also the source when a row says "author description". Version columns scope the evidence; an available
1.21.1 build does not prove that an older manual or newer development branch applies to it. Moving branches are
dated inspection references, not permanent release guarantees. This is document/source research: **no listed mod
was installed or tested in-game**. A screening result means no qualifying mechanism was established in the inspected
material, not that every release lacks it. Unconfirmed suggestions remain subject to future design; the confirmed
product direction above remains fixed.

## Coverage and relevance labels

- **100 projects**, numbered C001–C100; **92** have an inspected platform counter of approximately one million or more.
- **8 smaller specialists:** Integrated REST, Logistical Automation, Ender-Rift, OpenComputers II, Classic Peripherals, Create: Improve, Create: FluidLogistics, Create: Additional Logistics.
- **R: 70 rule/filter/observation/authoring references** with concrete relevant mechanisms. This includes finite controls and script APIs, not only full policy engines.
- **B: 28 narrower boundary comparisons**, such as identity scope, pack configuration, typed endpoints, displays or fixed capacity.
- **S: 2 screening records** with no resource-sharing policy or conditional authoring mechanism established.

Future design should qualify observable scope, effective versus configured permission, stock/concurrency semantics,
in-flight crafting effects and genuinely editable graph/script conversion. This survey chooses no runtime, DSL,
data model, polling interval or delivery sequence. The accepted baseline remains authoritative.

## Documentation verification

Run from the repository root. Python uses only the standard library. This checks the two 100-row catalogs,
distinct project identities/URLs, table shape, overlap totals, local document targets and whitespace in the
associated documentation, including newly created files that `git diff --check` does not cover.

```sh
python - <<'PY'
from pathlib import Path
import re

catalogs = {
    'F': Path('.omo/knowledges/federation-p2p-mod-survey-2026-10-03.md'),
    'C': Path('.omo/knowledges/custom-policy-mod-survey-2026-10-03.md'),
}
names = {}
for prefix, path in catalogs.items():
    rows = [s for s in path.read_text().splitlines()
            if re.match(rf'^\| {prefix}\d{{3}} \|', s)]
    assert len(rows) == 100, (path, len(rows))
    project_names, project_urls = [], []
    for number, row in enumerate(rows, 1):
        cells = [s.strip() for s in re.split(r'(?<!\\)\|', row)[1:-1]]
        assert len(cells) == 6, (path, number)
        assert cells[0] == f'{prefix}{number:03}', cells[0]
        project_names.append(re.search(r'\[([^]]+)\]', cells[1])[1])
        project_urls.append(re.search(r'\]\(([^)]+)\)', cells[1])[1])
    assert len(set(project_names)) == len(set(project_urls)) == 100
    names[prefix] = set(project_names)
    print(f'{path.name}: 100 unique, sequential, six-column entries')
assert len(names['F'] & names['C']) == 93
assert len(names['F'] | names['C']) == 107
paths = [Path('README.md'), *Path('docs/ideas').glob('*.md'), *catalogs.values(),
         Path('.omo/knowledges/federation-p2p-feasibility-2026-10-02.md'),
         Path('.omo/knowledges/custom-policy-ideas-2026-10-02.md')]
for path in paths:
    text = path.read_text()
    assert all(s == s.rstrip() for s in text.splitlines()), path
    for target in re.findall(r'\]\(([^)]+)\)', text):
        if target.startswith(('http://', 'https://', 'mailto:', '#')):
            continue
        assert (path.parent / target.split('#', 1)[0]).exists(), (path, target)
print('PASS: 93 overlapping / 107 distinct projects; local links and whitespace')
PY
git diff --check
```

Expected result: both catalog messages report 100 valid entries, followed by the PASS line; `git diff --check`
produces no output. Completed on 2026-10-03. Independent read-only reviews also checked the confirmed P2P semantics,
the full two-way editor requirement, and selected source attributions. No production-code or in-game validation
was performed for these documentation changes.
