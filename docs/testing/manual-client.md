# Manual real-client walkthrough (not yet performed)

From the repository root on a graphical desktop with Java 21, launch the interactive client:

```bash
./gradlew :neoforge-1.21.1:runManualClient --dependency-verification=strict --no-configuration-cache
```

Expected: Minecraft Java Edition reaches the title screen; a first-run accessibility prompt may need dismissal via Continue. Check the Mods list for AE2 Federation, Applied Energistics 2 and LowDragLib2, with Minecraft 1.21.1 / NeoForge 21.1.250. [Launcher smoke evidence](../../.omo/evidence/task-40-manual-client/verification.md) reached only the title background/accessibility prompt under Xvfb, with the production mod list in `neoforge-1.21.1/run-manual-client/logs/latest.log`; it created **no world** and performed **no human gameplay**. The launcher uses `sourceSets.main`, not the testmod, and does not require dedicated-server EULA approval for singleplayer. This walkthrough is exploratory, not the automated F3 run or its approval. The [automated scenario guide](commands.md) has exact `ui.*`, `bridge.*`, `router.*`, `policy.*`, `provider.*` and `endpoint.*` IDs; these are **Gradle case IDs**, not chat commands or in-game scripts.

1. Create a **new disposable Creative world** in this client, never a valued save. Its world files persist under the Git-ignored `neoforge-1.21.1/run-manual-client/saves/`. Put down two separately powered AE2 networks with distinct cable colors and a native ME Chest/cell on each. Place a multipart Bridge on an AE2 cable bus so its main cable side belongs to one Grid and its outward side touches the other. Keep the two Grids physically separate; don't connect an AE2 cable around the Bridge. Open the Bridge workspace. Expect two distinct native members and a shared direct Federation Domain, not a single merged ME network. Remove one outside neighbor: expect a disabled/diagnostic Bridge, not a usable stale route. Reconnect and reopen after settlement. Compare `bridge.valid`, `bridge.invalid`, `bridge.same-grid`, `bridge.reject-federation-cable`, `bridge.reload-replace`.
2. Build a separate Router with up to six independent face attachments. Use native AE2 connections and Federation Cable on different faces, never both on the same face. Connect a cable extension reciprocally to another Router/Federation Domain connection. Open the Router workspace and inspect the face/type and member diagnostics. Expect six independently classified ports; repeated attachment to one Grid does not create six independent native networks. An unsupported or ambiguous face must not activate. Compare `router.mixed-six-faces`, `router.six-independent-me`, `router.repeat-network`, `router.reject-unsupported`, `ui.multipart-attachments`.
3. On a powered source Grid with a native Crafting CPU, place an **ME Federation Pattern Provider** by clicking the side of an ME Federation Cable or Router: the face placed against the clicked block becomes its Federation face (cyan placeholder texture) and the other five faces join the source ME network; an AE2 wrench rotates it. Right-click the Provider to open AE2's own Pattern Provider screen and insert a real encoded Processing Pattern (the Pattern Access Terminal works too). Blocking, Lock Crafting and priority set in that screen apply to every Lane. Build three target Grids, each with its own **ME Federation Processing Endpoint** (its east face is the Federation face and is neither an input nor a return face), machine and return path, and attach those Grids to the same ME Federation Domain, for example on Router faces. Set directional Processing EXECUTE and SUPPLY Policy from the source network to each target. In a Router or Bridge workspace's Pattern mapping panel choose the Provider (**Next Provider**), the Pattern slot (**Next slot**) and an Endpoint (**Next target**), then **Toggle selected target**: the server claims that Endpoint for this Provider and allocates one native Lane for it. Repeat for the other two Endpoints, then submit a small native AE2 crafting order. Expect a native CPU/link, a selected Lane, physical target input, return through the owning Provider, and a physical source result. Don't infer all three ran from one completed order. Compare `provider.production-three-way`, `lane.native-three-way`, `provider.pattern-mapping`, `endpoint.federated`, `processing.native-differential`, `ui.mapping`, `ui.endpoint`.
4. Block one destination's machine input using its native Blocking setup, then repeat with the other two destinations clear. Expect the blocked Lane not to lock the others. Turn one directional rule OFF or delete it in the workspace, wait for server acknowledgment, and attempt the same route. Expect denial or a diagnostic, not silent fallback; a missing rule is not permission. Unplug/replug a Bridge or Router connection and reopen any stale editor before changing Policy. Expect stale context/revision rejection and restored access only when identity, Federation Domain and active Policy agree. Break the Provider afterwards: expect each Pattern to drop once, the Provider item to drop, and its Endpoints to become unclaimed. Compare `provider.production-revocation`, `provider.production-lifecycle`, `lane.reject-local-fallback`, `policy.lifecycle-matrix`, `policy.delete-reconnect`, `ui.shared-policy`, `ui.stale-context`.
5. Inspect Storage and Crafting from the native terminal, then close the workspace and verify native work remains owned by AE2. Optional addon testing must follow [the exact compatibility matrix](../compatibility/matrix.md), not a testmod machine. Record the first mismatch with the version tuple, world topology, comparison case ID, expected/observed quantities, errors and screenshots (Minecraft's F2 screenshot key writes under `neoforge-1.21.1/run-manual-client/screenshots/`). The client log is `neoforge-1.21.1/run-manual-client/logs/latest.log`. Don't label this walkthrough F3 evidence.

For cleanup, quit through Minecraft's menu and wait for the Gradle client process to exit. No automated cleanup runs: the world, screenshots and logs remain in `neoforge-1.21.1/run-manual-client/` for your inspection or next launch. Do not delete the directory or its worlds. If a step fails, stop that scenario and report the first mismatch rather than declaring subsequent steps passed.
