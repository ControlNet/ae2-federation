# AE2 Federation Blockbench workspace

This is an editable snapshot of the existing v1 game assets, prepared for the
next art iteration. It is not a new art proposal or an approved redesign.

Open `ae2_federation_overview.bbmodel` for the complete collection. The overview
uses Blockbench's Free Model format to place multiple devices outside a single
Minecraft block; **do not export it as one game block**.

Use the individual Java Block/Item projects to edit a device:

- `router.bbmodel`
- `pattern_provider.bbmodel`
- `processing_endpoint.bbmodel`
- `bridge.bbmodel` (actual NORTH-authored AE2 Part geometry)
- `cable_*.bbmodel` (nine representative connection masks)

All projects embed the real PNG textures, including the original animation
strips. They have no absolute texture paths or dependency on the original
website. Geometry, per-face UVs and disabled internal faces are imported from
the game resources. Cable layers are separate `solid`, `stream` and `glass`
groups; use the outliner eye controls to inspect their contributions.

## Open

From the repository root on the configured Linux workstation:

```sh
~/.local/bin/blockbench "$PWD/tools/blockbench/projects/ae2_federation_overview.bbmodel"
~/.local/bin/blockbench "$PWD/tools/blockbench/projects/pattern_provider.bbmodel"
```

The desktop application menu also has **Blockbench** and
**AE2 Federation - Blockbench** entries. These commands require a desktop
session. The assistant's launch verification used a separate virtual display.

## Editing and source ownership

Save an A/B candidate with **Save Project As** before experimenting. Embedded
textures can be painted and saved inside the project. Individual project files
are independent: changing a texture in the overview does not update another
project. Use the individual device project as the authority for that candidate.

Production resources remain generated by `tools/visual/build_assets.py`.
These Blockbench projects are art working files, not automatic build inputs.
After art approval, transfer the approved textures/geometry into the maintained
generation pipeline and run its validator. Do not directly overwrite a generated
production JSON and expect the edit to survive generation.

A normal Java export does not recreate NeoForge composite layer routing,
`neoforge_data`, all 64 cable selections, or AE2 Part registration. Those remain
in the existing integration. Blockbench's transparent preview can occlude some
internal cable surfaces differently from Minecraft; hide `glass` to inspect the
flow geometry and verify final transparency in the game. Texture strips retain
16 animation frames; the editor play control previews their animation.

The authored block axes are unchanged: Provider front SOUTH before blockstate
rotation, Endpoint front SOUTH before its fixed EAST placement rotation, Bridge
front NORTH before AE2 Part rotation. The overview is a separated collection,
not a simulated connected network.

## Recreate a baseline without overwriting art

The importer needs Python's standard library only; it installs no packages.
Run from the repository root and choose a new output directory:

```sh
python3 tools/blockbench/create_projects.py --output /tmp/ae2f-blockbench-baseline
```

Expected: 14 projects (13 individual models plus the overview). Existing target
files cause an error rather than overwriting hand edits. The baseline covers
cable masks 0, 1, 3, 12, 48, 17, 19, 51 and 63. Production still contains all 64.

## Verification

Blockbench 5.2.1 actually loaded all 14 files: no texture loading errors and no
unresolved face textures. Overview: 155 cubes, 43 groups and 20 embedded textures.
The animated textures were recognized as 16-frame strips. This is editor
verification, not a new Minecraft art acceptance run.

See `tools/blockbench/docs/editor-overview.png` for the actual editor capture and
`tools/blockbench/docs/installation.md` for installation provenance.

## Project-local MCP editing

For agent-assisted editing, use `./tools/blockbench/launch.sh` from the repository
root. It enables the pinned MCP plugin in a separate repository-local profile.
The ordinary Blockbench launcher does not enable MCP. See
`tools/blockbench/docs/mcp.md` for setup, usage, isolation checks and actual results.
Java device projects explicitly select the **1.9 - 1.21.5** format range
(`java_block_version: "1.9.0"`) so edits stay within Minecraft 1.21.1 constraints.
